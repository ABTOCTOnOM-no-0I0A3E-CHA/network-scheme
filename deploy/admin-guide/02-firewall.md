# 2. Порты и правила файрвола

## 2.1. Входящий трафик на сервер

| Порт | Сервис | От кого разрешить |
|---|---|---|
| 443/tcp | Панель (gateway) | Рабочие места пользователей панели |
| 8443/tcp | Origin executor'а `/x` (gateway) | Те же рабочие места: подтверждение изменений, терминал, ввод учёток записи |
| 514/udp, 514/tcp | Syslog (eventd) | Подсети управления |
| 6514/tcp | Syslog по TLS (eventd) | Подсети управления |
| 162/udp | SNMP-трапы и INFORM v2c (eventd) | Подсети управления |
| 22/tcp | SSH на хост | Только администраторы хоста (по ключам) |

У PostgreSQL порта на хосте нет. Порты eventd опубликованы на всех интерфейсах, но транзитный трафик к
ним принимается только из подсетей управления: установщик ставит правила `nms-ingress-*` в цепочке
`DOCKER-USER`. Eventd к тому же принимает события только от известных устройств (IP, для SNMPv3 —
совпадение USM-учётки); остальные отбрасываются и считаются.

## 2.2. Исходящий трафик с сервера

| Куда | Порт | Зачем |
|---|---|---|
| Подсети управления (`--mgmt-subnet`) | 161/udp | SNMP-опрос |
| Подсети управления | 22/tcp (или порт SSH устройства) | SSH-чтение (poller), сессии изменений (executor) |
| Подсети управления | 23/tcp | Только если для старых устройств явно включён telnet для чтения |
| Внутренние NTP (`--infra-ntp`) | 123/udp | Время хоста |
| Внутренние DNS (`--infra-dns`) | 53/udp, 53/tcp | Разрешение имён хоста |
| Внутреннее зеркало ОС (`--infra-mirror`) | 80/tcp, 443/tcp | Обновления пакетов ОС |

**Больше ничего.** Приложение не делает исходящих соединений (телеметрии, CDN, проверки обновлений
нет; телеметрия TimescaleDB выключена). Запретите на периметре весь прочий исходящий трафик сервера —
его не должно быть.

## 2.3. Egress сети `devices` (ставится автоматически)

Контейнеры, которые ходят к устройствам (poller, eventd, executor), сидят в сети `devices`. Из неё
разрешено только к подсетям управления, всё остальное отбрасывается в цепочке `DOCKER-USER`. Правила
записаны в `/etc/nms/config/egress.yaml` и применяются при каждом старте Docker:

- `ExecStartPre=nmsctl egress apply` — правила ставятся до любого контейнера; при ошибке Docker не
  стартует (fail closed);
- `ExecStartPost=nmsctl egress check` — если `FORWARD` не проходит через `DOCKER-USER`, Docker
  останавливается.

Вручную:

```sh
sudo nmsctl egress check    # правила на месте?
sudo nmsctl egress apply    # поставить заново (идемпотентно)
```

Важно:

- Перезагрузка или сброс хостового файрвола (`iptables -F` и т. п.) убирает правила `DOCKER-USER`.
  После этого — `sudo nmsctl egress apply` или `systemctl restart docker`. Хостовый файрвол не
  должен чистить чужие цепочки.
- `egress apply` только добавляет правила: разрешение для удалённой подсети управления остаётся до
  перезагрузки хоста или ручной очистки `DOCKER-USER`.
- Drop-in `/etc/systemd/system/docker.service.d/nms-egress.conf` при удалении продукта нужно удалить
  вручную, иначе Docker на хосте не запустится.

## 2.4. Трафик от контейнеров к самому хосту

`DOCKER-USER` фильтрует только транзитный трафик. Контейнер может обратиться к сервисам хоста через
`INPUT`, который Docker не трогает. Закройте хостовым файрволом от внутренних подсетей Docker
(`core`, `devices`, `xnet`, `edge`; по умолчанию `172.30.0.0/22`) все порты хоста: SSH, NTP/DNS-кэш,
агенты мониторинга и любые другие сокеты на `0.0.0.0` (проверка — `ss -lntu`).
