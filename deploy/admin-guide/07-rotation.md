# 7. Ротация ключей и сертификатов

Общее для всех команд:

- Новый секрет сначала пишется рядом как `<файл>.next` и подменяет старый rename'ом только после
  успеха. Прерванная ротация (сбой, Ctrl+C) **доводится повтором той же команды** — она продолжит со
  staged-ключа.
- Старый закрытый ключ после ротации удаляется: шифротекст, который не перезапечатан, больше не
  откроется.
- После любой ротации сделайте новый бэкап ([06-backup-restore.md](06-backup-restore.md)): старый
  архив ключей содержит прежние ключи.

| Команда | Что меняется | Простой |
|---|---|---|
| `nmsctl keys rotate read` | Ключ read-домена (учётки чтения устройств) | Рестарт api, poller, eventd |
| `nmsctl keys rotate write` | Ключ write-домена (учётки записи) | Executor остановлен на время ротации |
| `nmsctl keys rotate backup` | Ключ backup-домена (бэкапы конфигов, записи сессий) | Рестарт poller, executor остановлен |
| `nmsctl keys rotate ticket` | Ключ подписи session ticket'ов api → executor | Рестарт api и executor |
| `nmsctl executor key rotate [--yes]` | Ключ запечатывания executor'а | Executor остановлен; открытые сессии изменений прерываются |
| `nmsctl certs rotate [executor\|gateway\|syslog\|web\|all]` | Сертификаты сервисов от внутреннего CA | Рестарт затронутых сервисов |

## 7.1. Ключи доменов

```sh
sudo nmsctl keys rotate read
sudo nmsctl keys rotate write
sudo nmsctl keys rotate backup
```

Команда печатает новую версию и отпечаток ключа — сверьте его с панелью (браузер получает открытые
ключи из `keys.json`).

- **read:** api переходит на новую версию ключа и с этого момента принимает только учётки,
  зашифрованные на неё; все учётки чтения перешифровываются в одной транзакции с аудитом. Учётка, которая
  не открылась старым ключом, помечается недействительной — введите её в панели заново.
- **write:** executor перешифровывает все учётки записи одним изменением реестра.
- **backup:** новый открытый ключ получают poller и executor; executor перезапечатывает ключи
  шифрования (DEK) всех бэкапов конфигов, снимков перед сессией и записей сессий, тела шифротекстов не
  меняются. В выводе — счётчик записей, не открывшихся ни одним ключом (они остаются как есть).

## 7.2. Ключ session ticket'ов

```sh
sudo nmsctl keys rotate ticket
```

Ticket'ы, подписанные старым ключом, отвергаются сразу (ticket живёт 60 с, панель запросит новый).

## 7.3. Ключ запечатывания executor'а

```sh
sudo nmsctl executor key rotate
```

Executor останавливается, одноразовый контейнер проверяет MAC каждой строки реестра старым ключом,
пересчитывает MAC и перезапечатывает секреты TOTP изменений новым ключом в одной транзакции, затем ключ
подменяется и executor стартует. Подброшенная или изменённая строка роняет ротацию. Пока ротация не
доведена, executor остаётся остановленным (запущенный вручную — в freeze): повторите команду.

## 7.4. Сертификаты

```sh
sudo nmsctl certs rotate              # то же, что all
sudo nmsctl certs rotate gateway
```

| Имя | Сертификат | Перезапускаются |
|---|---|---|
| `executor` | Серверный TLS executor'а во внутренней сети `xnet` | executor |
| `gateway` | Клиентский сертификат gateway'я для executor'а; executor закрепляется на новом ключе (`gateway_spki_sha256`), старый отвергается | gateway, executor |
| `syslog` | TLS syslog (6514) | eventd |
| `web` | Веб-сертификат панели и `:8443`, если его выпустил внутренний CA | gateway |

- Сертификаты выпускаются на год. Новый ключ, те же имена.
- Корпоративный веб-сертификат (`--web-cert`) не перевыпускается: `all` его пропускает, `web`
  завершается ошибкой.
- Внутренний CA не ротируется: устройства доверяют `ca.crt` для TLS syslog. CA живёт 10 лет, его ключ
  не покидает хост.
