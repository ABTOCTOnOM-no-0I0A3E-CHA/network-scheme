# Демо-стенд

Локальный стенд network-scheme с симулированными устройствами — чтобы прокликать панель без реального железа.
Только для демонстрации: продуктовый код и умолчания не меняются, всё лежит в `test/demo/`.

## Что нужно

- Windows 11 + Docker Desktop (WSL2) и Git Bash, или Linux с Docker;
- Go и Bun в `PATH` (те же, что для разработки);
- свободный порт 443: адрес панели при установке — `https://localhost`, и проверки Origin требуют ровно его;
- ~6 ГБ на диске (образ TimescaleDB и кэш образов внутри стенда).

## Запуск

```bash
test/demo/up.sh
```

Запуск — 3–15 минут (сборка образов, загрузка их в стенд, `nmsctl install`; первый раз дольше, пока качаются
базовые образы), повторные быстрее: образы остаются в кэш-томе. В конце скрипт печатает адрес, логин и пути к паролю и TOTP.

- Адрес: **https://localhost**. Сертификат выпущен CA стенда (`test/demo/.run/ca.crt`): либо принять предупреждение
  браузера, либо импортировать этот CA в доверенные корневые (на время демо).
- Логин: `admin`, пароль — в `test/demo/.run/creds/admin-password`.
- TOTP: секрет — в `test/demo/.run/creds/totp-secret`. Добавьте его в приложение-аутентификатор как ключ, введённый
  вручную (аккаунт `admin`, по времени, 6 цифр, 30 с), или отсканируйте QR-код из `test/demo/.run/creds/install.log`
  (там же резервные коды). Каждый код принимается один раз — после входа следующий код (например, для подтверждения
  действий) появится через 30 с. Если код не подходит — проверьте время на Windows и в Docker Desktop (после сна
  ноутбука часы ВМ могут отставать; помогает перезапуск Docker Desktop).

`test/demo/.run/` в `.gitignore`: пароль и секрет генерируются при каждом запуске и никогда не коммитятся.

## Остановка

```bash
test/demo/down.sh            # удалить стенд, его данные и учётки (кэш образов остаётся)
test/demo/down.sh --purge    # плюс кэш-тома и демо-образы
```

После перезагрузки Windows или Docker Desktop стенд не поднимается сам: `down.sh`, затем `up.sh`.

## Что внутри

Всё работает внутри одного привилегированного контейнера `nms-demo` (systemd + свой Docker) — это «сервер», на
который ставится `nmsctl install`, как в CI-джобе e2e. Наружу опубликован только 443: проброс UDP-портов Docker
Desktop ломает SNMP с хоста до симуляторов, поэтому симуляторы живут в той же сети устройств, что и poller.

| Устройство | Адрес | Что это | Что показывает |
|---|---|---|---|
| `mes-access-1` | 172.30.1.11 | Eltex MES (SNMP + SSH-эмулятор) | инвентарь, бэкапы конфига, вкладка CLI, syslog |
| `esr-edge-1` | 172.30.1.12 | Eltex ESR (SNMP + SSH-эмулятор) | то же |
| `sw-floor-2` | 172.30.1.13 | обычный коммутатор | syslog и трап linkDown → открытая проблема |
| `rtr-branch-1` | 172.30.1.14 | обычный маршрутизатор | опрос и метрики |
| `topo-a` … `topo-d` | 172.30.1.201–204 | лаборатория топологии | связи LLDP/MAC на карте |
| `offline-1` | 172.30.1.250 | никто не отвечает | недоступное устройство |

Список — в `devices.txt`; симуляторы и отправители событий запускает `devices.sh` (внутри стенда), данные в панель
заносит `seed.ts` через API — группу «Демо-стенд», устройства с read-учётками, запечатанными ключом чтения, как это
делает браузер, и общий дашборд «Демо» со всеми 8 виджетами (дашборд по умолчанию для роли admin).

Учётки симуляторов (`demo-read` / `demo-read-pw`, SNMP community по имени файла данных) — тестовые значения
эмуляторов, как в e2e. Вкладка CLI отвечает на команды без аргументов (`show version`, `show system`,
`show interfaces status`, …); команды с аргументами эмулятор не знает.

## Если что-то пошло не так

```bash
docker exec nms-demo docker compose -f /etc/nms/compose.yaml ps     # сервисы стенда
docker exec nms-demo docker compose -f /etc/nms/compose.yaml logs --tail 100 poller
docker exec nms-demo docker ps --filter name=nms-demo-              # симуляторы
```

Скрипт отказывается стартовать, если контейнер `nms-demo` уже есть: сначала `down.sh`.
