# Демо на своём сервере и домене

То же демо, что `up.sh`, но для Linux-сервера: панель с симулированными устройствами по адресу `https://ваш-домен`.
Продукт не знает об интернете (нет ACME, CDN и внешних шрифтов), поэтому сертификат панели выпускает её собственный CA.
Для «зелёного замка» поставьте перед демо свой обратный прокси с обычным сертификатом (вариант Б).

## Что нужно на сервере

- Linux x86_64 или arm64, Docker 24+ с **cgroup v2** (Ubuntu 22.04+/Debian 12+), **4 ГБ ОЗУ и 30 ГБ свободного диска сверх
  того, что нужно остальным сервисам**: образы, собственный Docker демо и его база занимают около 25 ГБ, и скрипт не
  стартует, если свободно меньше (`--min-free-gb`). Заполненный диск останавливает все сервисы сервера, включая чужие базы;
  лучше всего держать демо на отдельной машине или VPS;
- выход в Docker Hub (образы собираются на сервере; Go и Bun ставить не нужно);
- DNS-запись домена (`demo.example.com`) указывает на сервер;
- свободный порт 443 (вариант А) или любой локальный порт для прокси (вариант Б).

Контейнер демо ограничен: своё пространство cgroup (не общее с хостом), лимиты `--memory` (по умолчанию 4g) и `--cpus`
(по умолчанию 2). Он работает в режиме `--privileged` (внутри него свой Docker и systemd, как в `up.sh`): не запускайте его
на сервере с чужими важными сервисами без нужды и не открывайте ничего, кроме порта панели.

## Запуск

1. Положите исходники на сервер. Вариант: `git clone` вашего репозитория на сервере (ветка `main`, коммит не ниже
   `10ac1e5`, плюс файлы `test/demo/server.sh`, `test/demo/SERVER.md` и правка `test/demo/seed.ts` из этой папки),
   либо распакуйте архив `nms-demo-src.tar.gz`, который я подготовил.
2. В корне исходников:

   ```bash
   bash test/demo/server.sh --domain demo.example.com
   ```

   Первый раз 10–25 минут (сборка образов и установка). Повторные запуски быстрее: образы лежат в томах.
3. В конце скрипт печатает адрес, логин `admin`, пути к паролю и секрету TOTP (`test/demo/.run/creds/`). Секрет TOTP
   добавьте в приложение-аутентификатор как ключ вручную (30 секунд, 6 цифр) или отсканируйте QR из `install.log`.

Открывать демо нужно **ровно по имени из `--domain`**: панель сверяет `Origin` и по IP-адресу не пустит.

**Про порт.** Скрипт публикует панель на `--listen` (по умолчанию `0.0.0.0:443`), любой другой адрес и порт тоже работают. Но
браузер должен видеть панель на стандартном 443: при `https://домен:8444` напрямую вход не пройдёт (ошибка CSRF), потому
что в `Origin` попадает порт. Нестандартный порт нужен только за прокси на 443 (вариант Б). Это проверено прогоном:
`--listen 127.0.0.1:8444` и запрос с `Origin: https://localhost` → вход проходит, с `Origin: https://localhost:8444` → 403.

## Вариант А: сертификат панели от её CA (проще всего)

Панель слушает 443 на сервере. Браузер покажет предупреждение о сертификате: примите его или импортируйте
`test/demo/.run/ca.crt` в доверенные корневые на своём компьютере. Для показа коллегам это неудобно, поэтому есть вариант Б.

## Вариант Б: ваш прокси с настоящим сертификатом

Опубликуйте панель только на локальном порту и поставьте прокси перед ней:

```bash
bash test/demo/server.sh --domain demo.example.com --listen 127.0.0.1:9443
```

Прокси должен передать панели исходный `Host` (имя домена) и не проверять её самоподписанный сертификат.

Caddy:

```
demo.example.com {
    reverse_proxy https://127.0.0.1:9443 {
        header_up Host {http.request.hostport}
        transport http {
            tls_insecure_skip_verify
            tls_server_name demo.example.com
        }
    }
}
```

nginx (сертификат Let's Encrypt вашего домена):

```
server {
    listen 443 ssl http2;
    server_name demo.example.com;
    ssl_certificate     /etc/letsencrypt/live/demo.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/demo.example.com/privkey.pem;
    client_max_body_size 4m;
    location / {
        proxy_pass https://127.0.0.1:9443;
        proxy_set_header Host $host;
        proxy_ssl_server_name on;
        proxy_ssl_name $host;
        proxy_ssl_verify off;
    }
}
```

Панель увидит адрес прокси вместо адреса посетителя: на демо это не мешает (лимиты попыток входа общие для всех).

## Безопасность

Устройства и данные в демо вымышленные, но панель настоящая. Пароль `admin` случайный, вход требует TOTP. Если демо
доступно из интернета, ограничьте доступ по IP на прокси или файрволе, когда показ закончен, остановите демо.
Исполнитель изменений (Фаза 4) в демо выключен и порт 8443 не публикуется.

## Управление

```bash
bash test/demo/server.sh --down            # удалить демо (кэш образов остаётся)
bash test/demo/server.sh --down --purge    # плюс кэш образов
```

После перезагрузки сервера контейнер демо поднимется сам (`--restart unless-stopped`), но симулированные устройства
запускаются отдельно: если после перезагрузки на карте всё «недоступно», выполните `--down`, а затем снова запуск.

Обновление до новой версии: обновите исходники, `--down`, снова `server.sh --domain …` (данные демо создаются заново).

## Если что-то не так

- `Origin`/вход не работает: открыли по другому имени или по IP. Используйте точно `https://<значение --domain>`.
- Скрипт упал на `docker pull` или сборке: нет доступа к Docker Hub с сервера (`docker pull ubuntu:24.04`).
- Контейнер не стартует (`systemd`): проверьте cgroup v2 (`stat -fc %T /sys/fs/cgroup` → `cgroup2fs`).
- Порт 443 занят: используйте вариант Б (`--listen 127.0.0.1:9443`).
